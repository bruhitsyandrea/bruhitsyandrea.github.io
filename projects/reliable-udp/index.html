Reliable File Transfer
over UDP

Building ordering and reliability on top of an unreliable transport protocol using sliding windows, acknowledgments, timeouts, and retransmissions.

C UDP Sockets Sliding Window Linux
THE PROBLEM

UDP doesn't promise
your packets will arrive.

The goal was to transfer a file between a client and server using UDP while still guaranteeing that the reconstructed file was identical to the original.

✕

Packet Loss

DATA packets and acknowledgments can disappear during transmission.

↕

Reordering

Packets may reach the server in a different order than they were sent.

◷

No Reliability

Unlike TCP, UDP doesn't automatically retransmit missing data or track acknowledgments.

DESIGN GOAL

Build reliability ourselves while still allowing multiple packets to remain in flight at once.

HOW IT WORKS

Making UDP
reliable.

Instead of waiting for every packet individually, the client keeps multiple packets in flight using a sliding window. Sequence numbers, acknowledgments, timeouts, and retransmissions provide the reliability that UDP does not provide by itself.

SLIDING WINDOW

Send first.
Wait less.

Instead of sending one packet and waiting for its acknowledgment, the client keeps a window of packets in flight. As packets are acknowledged, the base of the window moves forward and new packets can be transmitted.

WHY A WINDOW?

Reliability without sacrificing throughput.

Stop-and-Wait leaves the network idle while the sender waits for every acknowledgment. A sliding window allows several packets to travel simultaneously while still tracking which data has been successfully delivered.

CORE RESULT

Unreliable transport → reliable file transfer.

A transfer is considered successful only when the server reconstructs the file correctly and the client receives acknowledgment of the complete transfer.

WHAT I LEARNED

Reliability isn't magic.
Someone has to build it.

Building reliable transfer over UDP helped me understand what transport protocols are actually doing underneath the abstractions applications normally rely on.

01

Protocol Design

I learned how sequence numbers, acknowledgments, sliding windows, and retransmissions work together to create reliable communication.

02

Failure Is Normal

Network software has to assume packets can disappear, arrive late, arrive out of order, or never receive a response.

03

State Matters

Both client and server must carefully track packet state so that retries and out-of-order delivery do not corrupt the final file.
