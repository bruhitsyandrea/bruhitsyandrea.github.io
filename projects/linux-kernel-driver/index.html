Hello, Kernel

Kernel modules · Makefiles · printk · dmesg

+

What I built

My first loadable Linux kernel module. I built the module against the running kernel, loaded it with insmod, inspected its output through dmesg, and safely unloaded it with rmmod.

What I learned

This lab introduced me to the lifecycle of a kernel module and how kernel code is compiled, loaded, executed, and removed separately from normal userspace programs.

✓ COMPLETED

Character Device Driver

cdev · file_operations · read/write · copy_to_user

+

What I built

A character device backed by an in-kernel buffer with open, release, read, and write operations, plus a userspace C program for testing communication with the driver.

What I learned

I learned how the Linux VFS connects userspace operations to driver functions through struct file_operations and why data crossing the userspace/kernel boundary must use copy_to_user() and copy_from_user().

02
✓ COMPLETED

IOCTL Control Interface

ioctl · _IO · _IOR · _IOW · device commands

+

What I built

Extended the character driver with an ioctl interface for device-specific commands such as resetting the device, querying its status, and changing its operating mode.

What I learned

I learned why read and write are not enough for many real devices and how ioctl provides a structured control interface between userspace applications and kernel drivers.

03
✓ COMPLETED

PCI & MMIO

probe() · BAR · pci_iomap() · readl() · writel()

+

What I built

A PCI driver that binds to a virtual QEMU device, maps its Base Address Register into kernel address space, and performs register-level reads and writes through MMIO.

What I learned

This was where the project moved from a software-only character device into actual hardware-style driver development. I learned how the PCI subsystem discovers devices, calls probe(), maps device registers, and allows the driver to communicate with hardware through memory-mapped I/O.
